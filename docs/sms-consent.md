# SMS თანხმობა (ტესტი, ეტაპი 1)

მიზანი: 3-4 დღე შევამოწმოთ, თანხმდებიან თუ არა მყიდველები სარეკლამო SMS-ზე. SMS ჯერ არ იგზავნება.

## სად ჩანს

- **ხელით შეკვეთის ფორმა** (ადმინი და მენეჯერი), ტელეფონის ქვეშ ბლოკი „SMS თანხმობა“:
  - ღილაკები: „კი“, „არა“, „პასუხი არ არის“. თავიდან არცერთი არ არის მონიშნული (= ჯერ არ უკითხავს). „კი“ ავტომატურად არასდროს ინიშნება.
  - „შაბლონის დაკოპირება“ აკოპირებს ტექსტს და ჩაწერს „პასუხი არ არის“-ს (asked). ნომერი თუ უკვე სწორადაა შეყვანილი, მაშინვე ჩაიწერება, თორემ შეკვეთის შენახვისას.
  - „კი“ ან „არა“ ჩაიწერება შეკვეთის შენახვის მერე, შეკვეთის ნომრით.
  - 9 ციფრის შეყვანისას ჩანს, რა წერია ბაზაში ამ ნომერზე. „კი“ ან „არა“ თუ უკვე წერია, თავიდან კითხვა არ სჭირდება. შაბლონის დაკოპირება ამ პასუხს არ ცვლის.
- **შეკვეთის ბარათი** („მომხმარებლის ინფო“-ს ქვეშ): ამ ნომრის სტატუსი და ღილაკები. ცვლილება მაშინვე ინახება, მაგ. თუ მყიდველმა გვიან უპასუხა ან თანხმობა გააუქმა.
- **ანალიტიკა** (მხოლოდ ადმინი), ბლოკი „SMS თანხმობა“ არჩეული პერიოდისთვის: ჰკითხეს / კი / არა / პასუხი არ არის (პირველი კითხვის დღით) და „ჰკითხეს X / ხელით გატარებულიდან Y“ (ნომრებით: პერიოდის ხელით გატარებული შეკვეთების რამდენ ნომერს აქვს ჩანაწერი).

## ბაზა

`smsConsents/{ნომერი}` (ნომერი = 9 ციფრი, `5XXXXXXXX`, ისევე, როგორც შეკვეთაში):

| ველი | |
|---|---|
| `status` | `asked` / `yes` / `no`. ჩანაწერი რომ არ არის = არ უკითხავს |
| `askedAt` | პირველი ჩაწერის დრო (სერვერის) |
| `updatedAt`, `updatedBy` | ბოლო ცვლილება: დრო და ოპერატორი (uid, მეილი, სახელი) |
| `source` | `chat` |
| `name`, `orderNumber` | მყიდველის სახელი და შეკვეთა, რომელზეც ჩაიწერა |
| `historyCount` | ჩანაწერების რაოდენობა history-ში |

`smsConsents/{ნომერი}/history/{1,2,3…}`: ყოველი ცვლილება (status, at, by, orderNumber, source). დრო სერვერისაა. მერე ვეღარ შეიცვლება. ეს არის თანხმობის და გაუქმების ჩანაწერი (პერსონალურ მონაცემთა დაცვის კანონი, მუხლი 12).

შეკვეთის დოკუმენტი არ იცვლება.

## წესები (Firestore rules, ბლოკი 14)

- წაკითხვა (`get`) და ჩაწერა: ადმინი და მენეჯერი. სია (`list`, სტატისტიკა) და history-ს წაკითხვა: მხოლოდ ადმინი. წაშლა: მხოლოდ ადმინი (მონაცემების წაშლის მოთხოვნისთვის).
- ჩაწერა მიიღება მხოლოდ მაშინ, თუ: სტატუსი `asked`/`yes`/`no`-ა; ოპერატორი = შესული ანგარიში; დრო სერვერისაა; იმავე ჩაწერაში ემატება შემდეგი history ჩანაწერი (N+1) იმავე სტატუსით; `askedAt` არ იცვლება.
- **rules უნდა გამოქვეყნდეს push-მდე.** თორემ შეკვეთები შეინახება, მაგრამ თანხმობა ვერ ჩაიწერება (ოპერატორი ნახავს გაფრთხილებას).

## კოდი

`src/services/smsConsentService.ts` (წაკითხვა, ჩაწერა ტრანზაქციით, სია, შაბლონი), `src/pages/admin/components/SmsConsentControls.tsx` (ღილაკები + ბარათის ბლოკი), `SmsConsentStats.tsx` (ანალიტიკა), ცვლილებები `CreateManualOrderModal.tsx`, `OrdersManager.tsx`, `AnalyticsDashboard.tsx`-ში.

## შემდეგი ეტაპი (თუ ტესტი გამოვა)

მყიდველების გვერდი და ფილტრები, SMS-ის გაგზავნა (smsoffice), ფასის წინასწარი დათვლა, გაუქმების ბმული ყველა SMS-ში, კამპანიის პრომო კოდი. პირველ გაგზავნამდე კონფიდენციალურობის პოლიტიკაში უნდა დაემატოს სარეკლამო SMS.
